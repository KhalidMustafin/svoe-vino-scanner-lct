# Архитектура сканера «Своё Вино»

Документ по ТЗ §4: из каких слоёв состоит сервис и где между ними граница, какие у него
контракты, сколько времени тратит каждый шаг, на каких моделях и данных он стоит, что
показывают честные замеры и какие правовые рамки держит. Опора — код (ссылки `путь:строка`) и
замеры в [`research/`](research/README.md). Чисел не из кода и не из замеров репозитория здесь нет,
кроме живого окна голоса сомелье 25.09 (его журнал — вне репозитория, §10).

**Словарь.**
- **«То же вино»** — главная метрика: ответ засчитан, если это slug метки или карточка того же
  вина по правилу организатора (другой год урожая или дубль карточки — то же вино; другой сахар,
  цвет или сорт — другое). «Строго» — slug в точности (§7).
- **kr-test** — 309 розничных снимков карточек товаров krasnostop.ru (246 вин), отделённые до
  первой строки модели и открытые по разу на базу и на каждого кандидата. Отдельная оценка
  (уровни оптимистичны, §7);
  вторая половина набора, kr-dev, шла в разработку (§7).
- **R, R-оригиналы** — 65 «Реальных фото» организатора с вином каталога (у 63 — из выгрузки
  07.09, у R048 и R084 эталон — карточка живого портала), в исходном WebP;
  ближе всего к приватной проверке. Их JPEG-копии — срез R набора v2 (§7).
- **v2** — наша разметка 353 полевых кадров каталога (226 вин) по правилу «то же вино». Набор
  разработки: по нему принимались правила и на нём учился ранкер, поэтому его числа — не оценка.
- **Э1–Э8** — опыты плана точности 25–26.09, условия каждого записаны до замера
  ([`research/README.md`](research/README.md)). В сервисе Э1, Э2, Э4, Э6, Э7; Э3 — под
  выключенным флагом; Э5 и Э8 отклонены.
- **H5** — правило спорного кадра при p < 0,5: снять бонус соседа по визуальному кластеру и
  убрать кандидатов, чьи сахар или цвет спорят с прочитанными (§2, слой 4).
- **zmax** — агрегация счёта картинки: косинусы каждой пары «окно кадра × вид эталона»
  стандартизуются по всем векторам вида, затем берётся максимум по векторам slug (§2, слой 2).
- **Адаптер LW** — обученное линейное выбеливание (learned whitening) векторов SigLIP; с 26.09
  путь поиска по умолчанию (§2, слой 2, и «Нормализация фото»). Прежний путь без него —
  `SVS_CANDIDATE=off`.
- **«Лоза»** — наш отдельный проект ИИ-сомелье для «Своего Вина». Его репозиторий сюда не входит;
  движки сочетаний и профиля вкуса перенесены в `tools/loza_engines/` и `app/recommend/`.

Состояние — 27.09.2026. Цепочка поиска (слои 1–5) готова и замерена. С 26.09 путь поиска и
выбора по умолчанию — кандидат 2 фундаментального трека: обученный адаптер поиска и ранкер,

барьера сомелье перенесён и выключен (§10). Что ещё открыто — в §9, §10 и §12. Стек против

## 1. Коротко

- **Задача.** По фото бутылки найти одну карточку каталога Strapi из 2 103 и отдать её slug.
- **Как это делается.** Картинка даёт 20 кандидатов: векторы SigLIP проходят обученный
  адаптер поиска (линейное выбеливание). Текст этикетки даёт признаки согласия с каждым из них.
  Выбирает обученный слой: логистический ранкер на 34 признаках, обученный на 1 517 кадрах пула
  по выдаче адаптера. Прежний путь без адаптера — `SVS_CANDIDATE=off` (§2, слой 2).
- **После поиска.** Карточка по выгрузке организатора, «Не то вино?», похожие из других
  виноделен, «Моего вина здесь нет» и «Сомелье у полки» (§9).
- **Сомелье.** Ответ считают правила и движки на CPU; модель только пересказывает готовый пакет
  фактов, её текст проходит 12 проверок, а первый же скан её обрывает (§10).
- **Процесс.** Один процесс FastAPI и один воркер (`app/api/__main__.py:56-64`).
- **Модели.** Все открытые и работают на той же машине; облачных API и больших языковых моделей
  нет, обе рабочие модели вместе занимают около 7,2 ГБ одной видеокарты на 10 ГБ (§13):
  - SigLIP 2 so400m — в процессе сервиса, на видеокарте;
  - qwen3.5:4b — в Ollama, по HTTP: читает этикетку и (в тишину) говорит голосом сомелье;
  - rubert-tiny2 — смысловой слой барьера сомелье на CPU, по умолчанию выключен.
- **Скорость.** Публикуемая сборка 27.09, скрипт организатора, 100 «Реальных фото»: p50 1 216 мс,
  p95 1 496 мс, максимум 1 840 мс, дольше 3 с — ни одного
  ([`research/2026-09-27_results/RESULTS.md`](research/2026-09-27_results/RESULTS.md)). Прежний
  путь, 23.09, 20 новых кадров, два прогона: p50 2,04 с, p95 2,36 с
  (`research/2026-09-23_audit/clean_latency/pooled.out:1`). Адаптер поиска добавляет к кадру на
  видеокарте 7,9 мс CV p50 (окно E, §4).
- **Точность — по тесту, замороженному до работы** (§7). kr-test — половина krasnostop по винам:
  309 розничных снимков карточек товаров krasnostop.ru (не фото у полки), 246 вин. Его отделили коммитом до первой строки модели и открыли
  по разу на базу и на кандидата. «То же вино» — **94,5 % [91,7–97,0]** против 89,6 % [85,9–93,1]
  у прежнего пути: починки 18, поломки 3, p = 0,0015. Строго — 89,6 % против 82,9 %.
- **Где выигрыша нет.** На 65 реальных фото организатора (WebP, центральная бутылка) — 62 из 65
  вживую (27.09, top-5 — 63 из 65), у прежнего пути с Э7 — 63. Числа разметки v2 — набора
  разработки — справочные, не оценка: по v2 принимались правила Э1–Э7, и на нём же учился ранкер.


SigLIP и VLM вызываются под одним замком видеокарты (`app/api/service.py:644`, `:281-329`,
`:1052-1061`).
Ожидание замка вычитается из бюджета запроса. Интерфейс может прислать два скана сразу, а две
задачи на видеокарте с 10 ГБ памяти не помещаются. Голос сомелье берёт тот же замок только без
ожидания и отдаёт его по первому скану (§10): скан ждёт его не дольше обрыва сокета к Ollama.

**Прогрев.** Порт открывается только после прогрева в lifespan (`app/api/main.py:195-208`):
1. поднимаются веса SigLIP;
2. VLM загружается в память Ollama с бюджетом 60 с;
3. синтетический кадр проходит всю цепочку с боевыми таймаутами, до двух попыток
   (`app/api/service.py:114`, `:795-861`).

Итог — `ready` или `degraded` с причинами в `/v1/health`. Только после прогрева ворота сомелье
получают замок видеокарты, а сомелье — данные и голос (`app/api/main.py:205-207`).

**Слой 2 подробно.**
- **Окна кадра.** Их четыре: целиком, «бутылка» (0,2–0,8 по ширине), «этикетка» и «полоса»
  (`app/features/views.py:69-74`).
- **Модель.** `google/siglip2-so400m-patch14-384`, float32 (`app/api/config.py:41`, `:121`), батч 16
  (`app/features/embedder.py:39`). Веса берутся только из локального кэша Hugging Face
  (`app/features/embedder.py:138`).
- **Индекс** `visual-s2so400m.npz`: 2 103 slug, виды bottle, label и band. Всего 6 312 векторов
  размерностью 1152 во float16 (метаданные индекса: `n_slugs 2103`, `n_vectors 6312`).
  - На 3 вектора больше, чем 2 103 × 3: у `merlo-litavshhuk` второй эталон, это правка 23.09
    (`research/README.md`, «Правка эталонов 23.09»).
  - Под флагом `SVS_LIVE_CARDS=1` (Э3 25.09, по умолчанию выключен) — второй комплект
    `visual-s2so400m-live71.npz`: те же 6 312 строк и за ними 213 видов 71 карточки живого
    портала, чьего вина нет в CSV. Маска `base_rows` в индексе держит нормировку zmax по строкам
    CSV, и счёт карточек CSV не меняется (`app/features/index.py:71-111`, `:114-132`).
- **Агрегация zmax.**
  - Косинусы каждой пары «окно × вид» стандартизуются по всем векторам вида и
    возвращаются на шкалу запроса (`app/features/index.py:71-111`).
  - Затем берётся максимум по векторам slug и top-20 (`app/api/config.py:122`, `:186`).
  - Зачем: без выравнивания максимум выбирал пару с высоким фоном, а не лучшее совпадение
    (`configs/resolve/README.md`, раздел «Агрегация CV»).
- **Адаптер поиска LW** (по умолчанию с 26.09; `research/2026-09-26_fund/PREREG_final.md`, §2.1).
  Одна линейная карта на векторы SigLIP — обученное выбеливание (learned whitening):
  `x' = norm((x − μ) · W)`, `W` — 1152 × 1152, float32 (`LinearAdapter.apply`,
  `app/features/adapter.py:103`).
  - **Как обучена.** По 6 116 совпадающим парам «окно кадра — лучший вид верной карточки» из
    1 529 кадров каталога пула: студия, «телефон», v2, kr-dev и его same_packshot. Ни одного
    кадра kr-test в пуле нет (`protocol.assert_no_test`). Карта гасит направления, которыми кадр
    отличается от своего эталона: свет, фон, ракурс, телефон. Усадка 2,0 выбрана внутренним
    4-фолдом по винам.
  - **Где применяется.** К 6 312 строкам индекса — один раз при загрузке (`with_adapter`,
    `app/features/index.py:208`), к 4 окнам запроса — перед косинусами (`:373`). Дальше тот же
    zmax и top-20.
  - **Своя шкала счёта.** Порог отказа S10 0,3475 и порог подсказки «нет в каталоге» 0,4299 файл
    карты несёт сам: они пересчитаны тем же правилом, что у прежнего пути
    (`app/api/service.py:655-668`). Порог подсказки у этой карты перекрыт
    `SUGGEST_NOT_FOUND_VISUAL_MAX_BY_ADAPTER` (`app/api/config.py`): 0,4379 — то же правило
    (≤ 2 % кадров каталога по выдаче карты вне фолда), но по v2, kr-dev и R-оригиналам вместе, а
    не только по v2 (`research/2026-09-26_ooc/suggest_calibration.json`). Файл карты не меняется;
    действующий порог — в `/v1/health`, `model.suggest_not_found_visual_max`.
  - **Привязка к индексу.** Файл `index/cv-adapter-lw.npz` пачки данных: sha1 файла `206627c7…`,
    sha1 содержимого `5d25e5c6…`. Он собран под индекс `ccd3a01f…` (`app/api/config.py:93-99`).
    Сервис сверяет индекс при старте, и с другим индексом, без файла или с моделью, обученной на
    другой карте, не стартует. Причина отказа подсказывает `SVS_CANDIDATE=off`
    (`load_cv_adapter`, `app/api/service.py:350`; `_check`, `:730-741`). Поэтому живые карточки

    проверки на новых отложенных данных: kr-test для неё уже потрачен.
  - **Цена.** На CPU поиск по индексу — 5,6 → 6,8 мс p50, проекция 4 окон запроса — 0,86 мс,
    проекция индекса при старте — 0,19 с, память +5 МБ (`PREREG_final.md`, §5). Вживую на

    запись реплея и тело predict (`research/2026-09-26_fund/ship/ship_gate.json`).
    `SVS_CANDIDATE=adapter-lw` — отклонённый кандидат 1 (карта с `-goal`), только для повторов

### Нормализация фото

Подсказка кейсодержателя в ТЗ — поработать с нормализацией фотографии. Снимок у полки отличается
от эталона каталога (пакшот на прозрачном фоне) форматом, поворотом, фоном, кадрированием, светом
и камерой. Сервис сводит эти различия на трёх уровнях: пиксели, геометрия, признаки. Фильтров
яркости, контраста и резкости в цепочке нет, детектора бутылок — тоже.

**Пиксели** — `app/normalize/decode.py`. Байты разбираются один раз на запрос, дальше между
слоями ходит только массив RGB uint8, без перекодирования в JPEG (`decode.py:1-5`):
- формат — по сигнатуре байтов, а не по расширению: WebP часто приходит как `.jpg`. Разбираются
  JPEG, PNG, WebP, GIF, BMP, TIFF, HEIC и AVIF (`sniff_format`, `:55-84`);
- поворот по EXIF — до любых вырезов (`ImageOps.exif_transpose`, `:241`). Эталоны каталога
  при сборке индекса поворачиваются так же (`read_rgba`, `scripts/build_index.py:45-55`);
- 16-битные PNG и TIFF переводятся в 8 бит растяжением диапазона, а не обрезкой выше 255
  (`_to_eight_bits`, `:150-164`);
- прозрачность сводится на фон: для поиска — серый 128, как у эталонов
  (`app/features/views.py:49`), для чтения — белый (`decode.py:32`). Оба кадра — из одного разбора
  (`decode_on_backgrounds`, `:203-261`; вызов — `app/api/service.py:1028-1029`);
- JPEG больше 60 Мп разжимается сразу уменьшенным в 2, 4 или 8 раз, остальные форматы больше
  предела — `DecodeError` (`MAX_PIXELS`, `:26`; `_draft_under`, `:110-127`);
- размер меняется `INTER_AREA` при уменьшении (без муара на мелких буквах) и Ланцошем при
  увеличении (`resize_long_side`, `:264-281`). Читателю этикетки кадр уходит целиком: 1024 px по
  длинной стороне, JPEG качества 92 (`app/reading/readers/ollama_vlm.py:41`, `:289`).

**Геометрия** — `app/features/views.py`, `app/features/embedder.py`. Бутылка по условиям кейса
в центре кадра, поэтому кадр режется по долям сторон, а не по рамке детектора
(`from_query(image, None)`, `app/api/service.py:1056`):
- четыре окна запроса: кадр целиком, «бутылка» (0,2–0,8 по ширине), «этикетка» и «полоса»
  (`QUERY_WINDOWS`, `views.py:69-74`) — из кадра, уменьшенного до 896 px (`from_query`,
  `:165-196`; `MAX_SIDE`, `:46`). Одно из окон накрывает бутылку плотно почти при любом
  кадрировании;
- эталон каталога: пустые поля обрезаются по альфе, фон заливается серым 128, затем три вида —
  бутылка, этикетка (30–85 % высоты) и её центральная полоса 60 % ширины, увеличенная в
  1,5 раза (`from_packshot`, `from_bottle`, `views.py:109-162`; границы — `:36-41`);
- каждое окно и каждый вид вписываются в квадрат 448 px с белыми полями, без центрального
  кадрирования: иначе процессор модели срезал бы верх и низ высокой бутылки вместе с частью
  этикетки (`letterbox`, `app/features/embedder.py:31-58`).

Детектор бутылок есть в стенде (`app/detect/bottles.py`, `bench.ocr_bench --target detector`),
но в цепочку сервиса не входит.

**Признаки** — `app/features/adapter.py`, `app/features/index.py`:
- **адаптер LW** — `x' = norm((x − μ) · W)` к 4 окнам запроса и к строкам индекса
  (`LinearAdapter.apply`, `adapter.py:103-110`). Обученное выбеливание гасит направления,
  которыми снимок отличается от своего эталона: свет, фон, ракурс, камеру телефона. Это
  нормализация, выученная по 6 116 парам «окно кадра — вид верной карточки», а не заданная
  руками (§2, слой 2);
- **zmax** — косинусы каждой пары «окно × вид» стандартизуются по всем векторам вида
  (`align_pairs`, `index.py:71-111`). Полоса этикетки похожа на любую этикетку каталога сильнее,
  чем кадр целиком — на любую полосу, и без выравнивания максимум выбирал пару с высоким фоном,
  а не самое близкое совпадение.

## 3. Контракты

### `POST /v1/eval/predict` — для скрипта организатора

- **Всегда HTTP 200** (`app/api/main.py:241-253`). Скрипт засчитывает только 200/201 и непустую
  строку `.slug` (`app/api/main.py:3-5`).
- **Тело** — `ScanResult` без поля `evidence` (`app/api/service.py:156-163`). Ключи: `slug`,
  `confidence{top1,top5}`, `margin`, `top5[{slug,score}]`, `outcome`, `degraded`, `timings_ms`,
  `error`.
- **`outcome`:**
  - `matched`;
  - `ambiguous` — p < 0,5, но slug отдаётся;
  - `out_of_catalog` — только при `SVS_ABSTAIN=ooc_only`;
  - `error` — slug null.
- **Код ошибки** стоит в начале `error`: `decode:`, `too_large:`, `no_image:`, `bad_request:`,
  `cv:`, `internal:` (`app/api/main.py:138-169`, `app/api/service.py:997-1040`).
- **Инвариант: тело predict не меняется ни на байт.** Новые поля функции после поиска и сомелье
  добавляются только в `scan_body` (`app/api/service.py:165-182`, `:978-994`) и в отдельные
  маршруты. Ни одного нового поля в модели `ScanResult` нет (договор, §0). Хуки ворот сомелье
  стоят вокруг скана, но тела не касаются (`app/api/main.py:221-253`). Тело сверяется побайтно
  с эталоном, записанным до слоя после поиска (`tests/unit/test_predict_unchanged.py`).

### `POST /v1/scan` — для страницы продукта

То же тело плюс (`app/api/main.py:255-268`, `app/api/service.py:978-994`):
- `evidence` — кандидаты CV, прочитанные строки и поля, вход и выход resolve, условия правила
  отказа `abstain` (пишутся всегда, `app/api/service.py:1199-1227`);
- `card` — карточка найденного вина, тот же объект, что `GET /v1/wines/{slug}`;
- `candidates` — top-5 с именем, винодельней и `photo_url`, без счётов
  (`app/api/after_layer.py:656-669`);
- `after` — подсказка экрана (`after_block`, `app/api/after_layer.py:1080-1133`):
  - `state`: `found | check | not_found | error`;
  - `reasons`;
  - прочитанное `read` и строка `read_label` для «Прочитали на этикетке: …»;
  - `winery_in_catalog` и `winery_slugs` — есть ли прочитанная винодельня в каталоге и её вина;
  - `suggest_not_found` — подсказка «Похоже, этой бутылки может не быть в каталоге»; есть
    всегда, при `error` — `false` (правило ниже);
  - `question` — один вопрос сомелье на экране `check` по полю, которым различаются варианты
    (договор сомелье, §5; `question_candidates`, `app/api/after_layer.py:1140`); иначе `null`.

Винодельня каталога засчитывается только по однозначному написанию: имя винодельни целиком
или написание ровно одной винодельни. Родовое слово («шато», «chateau», «domaine», «estate»,
«усадьба», «villa», «долина», «хозяйство», «кооператив») и слово нескольких виноделен её не
называют (`GENERIC_WINERY_WORDS`, `specific_key`, `resolve_winery`,
`app/api/after_layer.py:284-291`, `:695-712`, `:741-791`). Винодельню, которую строки VLM
называют словом хозяйства и которая не похожа ни на одну винодельню каталога, слой отдаёт как
прочитана и с `winery_in_catalog: false` (`winery_of_lines`, `app/api/after_layer.py:355-372`).

Сбой слоя после поиска скан не прячет: ответ уходит с карточкой из разметки, без кандидатов и с
подсказкой по одному ответу (`app/api/service.py:985-994`).

**Правило `state`** (договор, §2; `scan_state`, `app/api/after_layer.py:152`): `error` при
ошибке. `check` — при отказе, без вероятности, при `ambiguous` или при p < 0,5. Иначе `found`.
`not_found` сервер не возвращает: этот экран открывает кнопка «Моего вина здесь нет».

**Подсказка `suggest_not_found`** (договор, §2; `visual_low`, `after_block`,
`app/api/after_layer.py:1075-1077`, `:1108-1112`): счёт CV лучшей серии (zmax,
`evidence.abstain.best_visual`, иначе счёт CV top-1) ниже `SUGGEST_NOT_FOUND_VISUAL_MAX = 0.8024`
(`app/api/after_layer.py:123`). Тогда флаг `true`, `found` становится `check`, а к `reasons`
любого экрана, кроме `error`, добавляется код `visual_low`. Экрана `not_found` подсказка не
открывает никогда; slug, `card`, `top5` и тело `/v1/eval/predict` не меняются. Калибровка на
записанных ответах поля ([`research/2026-09-24_after/hint.md`](research/2026-09-24_after/hint.md),
`calibrate_hint.py`) — наибольший порог, при котором флаг стоит не больше чем на 7 из 353
кадров каталога:
- на каталоге флаг на 6 из 353 (вне выборки, 5 фолдов по винам, — медиана 8);
- `found` → `check` на 4 из 295 `found`, и на всех четырёх сервис ответил верно;
- на 409 кадрах вне каталога флаг ловит 263 (64,3 %; вне выборки — медиана 58,2 %).

Эти числа — прежний путь (`SVS_CANDIDATE=off`). **На пути по умолчанию** у карты адаптера своя
шкала счёта и свой порог — 0,4379 (§2, слой 2): флаг стоит на 14 из 726 кадров каталога (v2,
kr-dev и R-оригиналы, вне фолда), вне каталога ловит 236 из 408 кадров ooc_v2 (57,8 %)
(`research/2026-09-26_ooc/suggest_calibration.json`; договор «после поиска», §2).

**Подсказка `not_found` откалибрована и выключена.** Правило в коде есть
(`not_found_conditions`, `not_found_reasons`, `app/api/after_layer.py:826-850`, `:1058-1072`):
счёт CV лучшей серии (zmax) ниже порога и одно из двух — каждая позиция прочитанной винодельни
каталога спорит с этикеткой по сахару, цвету или сортам либо винодельня названа словом
хозяйства и её в каталоге нет. Калибровка на записанных ответах поля
([`research/2026-09-24_after/hint.md`](research/2026-09-24_after/hint.md)): при пороге 0,8543
ложных `not_found` 7 из 353 кадров каталога (≤ 2 %; порог подобран на них же, вне выборки —
медиана 8), полнота на 409 кадрах вне каталога — 19,3 % (79). Это ниже 50 % по плану, поэтому
порога нет: `NOT_FOUND_VISUAL_MAX = None` (`app/api/after_layer.py:114`). Без порога полнота не
выше 20,3 %: мешает чтение, а не порог.

## 10. Слой 7: Сомелье

Договор — [`docs/api-sommelier.md`](docs/api-sommelier.md), модули — `app/sommelier/` (пакет не
знает FastAPI) и маршруты `app/api/somm.py`. Главное правило: **ответ считают правила, модель
только пересказывает**. Вердикт пары, блюда, вина подборки, подача и числа посчитаны на CPU до
того, как модель что-то увидела; шаблон ответа уже на экране. Живой текст — украшение, которое
приходит, только если видеокарта свободна от сканов, модель успела и текст прошёл проверки.

### Путь ответа

```
карточка  GET /v1/wines/{slug}/sommelier → заметка-шаблон («Текст и подбор — алгоритм»),
          профиль по 8 осям, подача, три блюда с чипами правил, чипы входа
   ▼ чип или вопрос (≤ 200 символов) + контекст прошлого хода
лист      POST /v1/sommelier/ask                                   app/api/somm.py:351-404
   ▼
[маршрут] липкий отказ → беседа → барьер правил (→ смысловой слой, если включён)
          → намерение со слотами → unknown                         app/sommelier/router.py:8-28
   ▼ этапы card / rules / catalog
[ответ]   правила сочетаний, подача, «Сомелье у полки», похожие → пакет фактов
                                                                   app/sommelier/answers.py:709
   ▼ событие facts: шаблон на экране сразу
[голос]   блюда с «да»: ворота видеокарты → qwen3.5:4b пересказывает пакет → 12 проверок
          (этапы voice / verify)                                   app/sommelier/voice.py:189-243
   ▼
text: проверенный текст модели или шаблон с причиной → done
```

- **Карточка** (`Sommelier.card`, `app/sommelier/answers.py:670`) — без модели и без видеокарты.
  Заметка «Сомелье · коротко» — всегда шаблон из фактов (`note_text`,
  `app/sommelier/templates.py:182-204`): живой текст бывает только в листе.
- **Поток** — NDJSON (`app/api/somm.py:499-592`): `facts` уходит сразу после расчёта, голос
  идёт после него, и его этапы приходят, только когда они действительно идут. Клиент закрыл
  поток — голос и ожидание этапа отменяются.

### Ворота видеокарты: скан всегда первый

`SommGate` (`app/sommelier/gate.py:1-22`) не подменяет замок видеокарты сервиса и не меняет его
семантику: скан берёт его с таймаутом, как раньше, а голос — только без ожидания. Хуки — два в
пути скана, остальное — при старте:
- ворота создаются в `create_app` до сборки сервиса (`app/api/main.py:193`), чтобы хуки
  работали и до неё;
- `run_scan`: `scan_started` первым делом, ещё до чтения кадра (`app/api/main.py:223`),
  `scan_finished` в `finally` (`:238-239`); `scan_started` обрывает активный голос
  (`app/sommelier/gate.py:146-154`);
- маршрут predict: `predict_done` в `finally` (`app/api/main.py:250-252`) продлевает тихое окно
  (`app/sommelier/gate.py:164-171`) — скрипт организатора шлёт кадры подряд, и пауза между ними
  ещё не тишина;
- lifespan: `gate.bind(svc.gpu_lock)` после прогрева (`app/api/main.py:205-206`) — голос не
  спорит с прогревом;
- полевой контур: приём кадра — тоже скан, без тихого окна (`FieldScanGate`, `:97-121`, `:309`).

Голос входит (`try_enter`, `app/sommelier/gate.py:174-192`), только если ворота связаны с
сервисом, скана в работе нет, тихое окно прошло и замок свободен прямо сейчас; иначе причина
`not_ready`, `busy`, `quiet` или `locked` и шаблон. Методы ворот исключений не бросают. Два
последствия для клиента Ollama (`app/sommelier/ollama_text.py`):
- **обрыв без ожидания.** Клиент говорит HTTP/1.1 прямо на неблокирующем сокете и ждёт в
  `select` сразу сокет Ollama и будильник: `socket.shutdown` из чужого потока на Windows не будит
  заблокированный `recv` (договор, §6.2). Скан ждёт замок ≤ 300 мс p95 (§4);
- **ничего медленного под замком.** Имя хоста Ollama разрешается до входа в ворота
  (`app/sommelier/voice.py:211-214`): `getaddrinfo` не оборвать. Ollama не ответила — голос 30 с
  её не зовёт (`UNAVAILABLE_BACKOFF_S`, `:100-102`), иначе каждый вопрос держал бы замок на время
  отказа соединения. Соединение, не установленное за весь срок голоса, — тоже «не ответила»
  (`connect_timeout`): у `localhost` на Windows два адреса, и их отказы по 2 с складываются.

Опции голоса зеркалят читателя этикетки (`OllamaText.mirroring`,
`app/sommelier/ollama_text.py:269-283`): та же модель, `keep_alive` и `num_ctx`, без параметров
загрузки — иначе Ollama перезагрузила бы модель, и скан заплатил бы 3–4 с. Это сверяет тест
(`tests/unit/test_somm_no_reload.py`).

### Маршрут, барьер и отказы

Маршрут детерминированный, как у «Лозы»: видно, какое слово к какому ответу привело
(`app/sommelier/router.py:1-28`). Слова блюда правил в вопросе ещё не блюдо правил: «рыба с
овощами», «салат с курицей», «жареная картошка» — «такого блюда нет» с чипами, а не ответ об
Овощах на гриле, Греческом салате и Запечённой картошке (`DishIndex._other_dish`,
`app/sommelier/router.py:383`). Барьер (`app/sommelier/barrier.py`) — правила, а не модель:
один и тот же отказ на один и тот же вопрос. Темы по старшинству — несовершеннолетние, медицина,
зависимость, трезвость, вождение, здоровье, крепкий алкоголь и пиво, покупка, цена, рецепты;
первые четыре липкие — отказ держится весь разговор через `context.refusal_topic`
(`app/sommelier/barrier.py:14-20`). Цена — всегда отказ: сервис её не знает и о ней не говорит.
Чип сразу даёт намерение, перед ним стоит только липкий отказ. Приёмка — тесты: маршрут ≥ 90 %
фраз набора на заглушках и на полной сборке данных, отказы, беседа и блюда — без промахов
(`tests/unit/test_somm_router.py:106`, `:156`), наборы отказов сквозь весь маршрут — все
(`:180`).

**Окольная речь** — классы, а не строки (раздел «окольная речь» в `app/sommelier/barrier.py`):
питьё привычкой и доза бутылками, похмелье и желание опьянеть, прятки питья, школа и ровесники,
вождение без слова «руль», кормление и роды, лекарства названием, орган с симптомом, способ
покупки; у каждого класса — законные соседи, которых правило не трогает. На отложенном наборе,
написанном независимо от правил (`research/2026-09-24_somm/heldout_eval.py`), отказов было 191 из 273 опасных
(17 доходили до вердикта), лишних — 15 из 290 законных; после правки — 273/273 и 1/290, но набор
правился по своим пропускам: свой набор по классам при первом прогоне — 53/56 (подробно — договор,
§4.4). Перепроверка 25.09 мерила свежими наборами, каждый написан до правки, которую проверяет: A — 18/40
до правки (шесть пропусков доходили до вердикта и голоса), B — 30/40, C — 25/30 и до последней
правки, и после. Правила по классам ловят около четырёх пятых свежего опасного, пропуски уходят в
«Вот что я умею», тему справочника или факт карточки; свободный ввод на показе (`SVS_SOMM_INPUT`)
— решение команды.

**Смысловой слой** (`app/sommelier/safety.py`, `SVS_SOMM_SAFETY`) — перенос `nlu/safety.py`
«Лозы»: rubert-tiny2 сравнивает вопрос с эталонами тем, ближайшие голосуют. Слой односторонний:
его спрашивают, только когда правила промолчали, и он может лишь добавить отказ, но не снять
(`app/sommelier/safety.py:10-12`, тест `tests/unit/test_somm_safety.py:157`). Веса — только из
локального кэша, на CPU; нет весов — `status: missing` и одни правила. **Выключен по замеру**
(`research/2026-09-24_somm/safety_eval.py`, `.json`): сквозь весь маршрут на 208 опасных и 594
законных фразах ни на одном пороге модель не добавляет отказ, не добавив и лишнего (при пороге
«Лозы» 0,75 — +9 и +10, с 0,84 — ни того ни другого).

### Пакет фактов: что видит модель

`FactsPackage` (`app/sommelier/answers.py:242-253`): `public` — тело события `facts`, остальное —
для голоса и проверок. Модель получает системный промпт «только факты» и одно сообщение:
намерение нашей формулировкой, строки фактов и готовый ответ (`app/sommelier/voice.py:114-128`).
Строки фактов — название, винодельня, регион, стиль, сорта, подача, блюда с подписями правил и
вердиктом словом, вина подборки (`_voice_lines`, `app/sommelier/answers.py:1531-1567`).
**Никогда:** вопрос гостя, описание из выгрузки, ароматические дескрипторы приоров, числа
профиля, контекст разговора. Вход не длиннее 2 100 символов (≈ 700 токенов русского текста);
длиннее — срезаются строки вин с конца (`app/sommelier/voice.py:89-95`).

### Проверки и откат на шаблон

Текст модели показывается, только если прошёл все 12 проверок по порядку (`GUARDS`,
`app/sommelier/guards.py:41-54`; `check` — `:378-421`): рассуждение вместо ответа, пусто, длина,
обрыв, мета-преамбула, блюдо названо вином, ложный отказ, числа не из пакета, имена не из пакета
(замок сущностей по `vocab.json`, `app/sommelier/entity_lock.py:281`), ароматические слова не из
пакета, стоп-лист (превосходные степени, оценки, призывы, цены, `%` не в «% об.»),
`content_filter`. Прошёл — метка «Текст — ИИ, подбор — алгоритм» и кэш в памяти процесса. Иначе
`text` равен шаблону с меткой «Текст и подбор — алгоритм» и кодом причины
(`REASONS`, `app/sommelier/voice.py:57-71`): намерение не пересказывается, `plain`, голос
выключен, ворота не впустили, скан оборвал, не успел, Ollama недоступна, проверка забраковала,
ошибка, клиент ушёл. В потоке стоит ещё одна сетка: живой текст, который не прошёл
`content_filter`, заменяется шаблоном (`app/api/somm.py:477-479`).

**Голос — только блюда** (решение 25.09, `answers.VOICED`, `app/sommelier/answers.py:119-123`):
пересказываются `what_to_eat` и `dish_check`, а подборки («Помягче», «Посвежее», «Чем заменить»,
финал «Помогите выбрать») — всегда шаблон с `reason: "not_voiced"`. Причина — замер окна
видеокарты 25.09: в 10 из 40 прошедших проверки подборок модель выдала вино карточки за вино
подборки, а замок сущностей такую подмену не видит (имя якоря в пакете есть); 30 из 30 ответов о
блюдах были верными. На тех же текстах сняты три вида лишнего брака — совет подачи «лучше
подавать», «соль» и «виноград» как родовые слова, «морские ноты» рядом со словом пакета (договор,
§6.5): доля прошедших у голосовых намерений — 248 из 252 (0,984, было 0,952), неверных текстов
не отпущено.

**У блюд голос — только «да» без подборки** (25.09, вечер; `answers.voice_fits`,
`app/sommelier/answers.py:221-238`): `dish_check` с оговоркой, «скорее нет» или «правила молчат» —
шаблон с `reason: "not_voiced"`, модель не зовётся. Повторное окно видеокарты на слитом коде
(`c0c4324`) прошло условия плана — 166 из 175 настоящих пакетов (0,949), перезагрузок 0, — но разбор
всех 12 прошедших текстов `dish_check` с вердиктом не «да» нашёл 6 грубых ошибок из 8 при «скорее
нет» (Wilson 95 % [0,41; 0,93]): вердикт перевёрнут («к утке с яблоками подходит розовое брют» при
«скорее нет»), вино карточки выдано за вино подборки. Все такие пакеты несут вина подборки, и это
тот же сбой, что у подборок: проверки его не видят, имена в пакете есть. Чипы карточки дают «да»
(120 из 120), вердикт не «да» — вопросы текстом (4 из 12), так что без ворот ошибался бы примерно
каждый пятый ответ на вопрос текстом о блюде; заодно ушли самые длинные входы модели (697 токенов
при потолке 700 — только у пакетов с подборкой). Принцип — голос только там, где он не лжёт, а
шаблон верен всегда: те же тексты разбора лежат в `tests/fixtures/somm_recorded/`, и ни один их
пакет ворота не пропускают (договор, §6.5).

### Данные `data/somm`

Собирает `scripts/build_somm.py` на CPU (`scripts/build_somm.py:1-49`); сервис только читает
готовые файлы — один раз при старте, без движка (`load_somm_data`,
`app/recommend/somm_data.py:645`; каталог — `SVS_SOMM_DIR`). Нет файла — заглушки договора
(`tests/fixtures/somm/`) или пусто: сервис стартует всегда.
- **Входы** — только выгрузка организатора (через `gt_tokens.jsonl` и CSV), наш словарь групп,
  приоры сортов и справочники «Лозы». Факты вина — теми же функциями, что у карточки сервиса
  (`app/recommend/catalog.py`).
- **Движок «Лозы» — в подпроцессе** `python -I -S tools/loza_engines/run.py`
  (`run_engine`, `scripts/build_somm.py:796-808`): пакет «Лозы» называется `app`, как у сканера,
  поэтому её код лежит в `tools/loza_engines/` под своим именем и видит только себя
  (`tools/loza_engines/__init__.py:1-6`). В работе сервиса движка и `safe_eval` нет.
- **Наша накладка** `tools/loza_engines/overlay.json` меняет условия одиннадцати правил «Лозы»
  (терпкое красное к рыбе и морепродуктам, «бульон» — только супам, сладкое к несладкому, но не к
  сыру и орехам, «пузырьки» — только жареному, три правила десерта — только десертам, «сладость
  оттеняет солёное» — только салу, «разная сила вкуса» — только вину слабее блюда, «крепость
  перекрывает блюдо» — не сладкому к орехам, «сладость спорит с блюдом» — не догадке по названию
  к ухе и кулебяке), вес и объяснение — никогда; пять своих правил сканера — целиком в разделе
  `added` (`tools/loza_engines/overlay.json:63`): вино сильнее блюда и полусладкое к несладкому
  солёному — оговорка, сладкое по карточке к рыбе — «скорее нет» (вес −3), сладкое только по
  названию к рыбе — оговорка с условной фразой (правило-оговорка, вердикт не решает:
  `HEDGE_RULES`, `verdict_of`), сладкое и креплёное к сыру и орехам — «да» (третий круг перепроверки
  25.09). Причины записаны в файле.
  Вину без сахара в выгрузке сладкие блюда — `neutral` без правил: сборка не называет его сухим
  (`sugar_decides`); креплёное, десертное или мускатное название без сахара — для правил возможно
  сладкое (`rule_sugar`, `scripts/build_somm.py:239`): портвейну больше не «подходят» устрицы, но
  и «скорее нет» с фразой о сахаре к рыбе ему не ставится. Догадку снимают название оранжевого

- **Право на сборке.** Каждая строка каждого файла проходит `content_filter` и стоп-лист;

### Что не пишется никогда

Вопрос гостя — ни текстом, ни отрывком, ни длиной — не попадает ни в журнал, ни в метрики, ни в
исключения; не пишутся и контекст разговора, и текст модели (`app/api/somm.py:12-15`,
`app/sommelier/voice.py:1-29`). Ошибка сборки ответа пишется типом исключения и кадрами стека
без сообщения — в нём могло бы оказаться слово вопроса (`app/api/somm.py:466-468`); slug не из
каталога не пишется (`:373-376`); смысловой слой пишет только тему и долю голосов. На вопрос —
одна строка INFO с кодами: намерение, вход, чип, причина голоса, проверка, время
(`app/api/somm.py:582-592`). 422 маршрутов сомелье не повторяет присланное: в `detail[]` только
`type`, `loc` без ключей гостя и `msg` (`app/api/somm.py:101-138`). Тесты:
`tests/unit/test_somm_api.py:1138`, `:1259`; `tests/unit/test_somm_voice.py:381`.

### Выключатели и `/v1/health.somm`

Переменные читаются в одном месте (`SommSettings`, `app/sommelier/settings.py:1-17`) и входят в
`ServiceSettings.somm` (`app/api/config.py:214-217`, `:321-324`): неверный флаг — отказ старта с
кодом 2, как у остальных `SVS_*`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `SVS_SOMM_LIVE` | `1` | `0` — живого голоса нет, ответы листа — шаблон с `reason: "off"`; Ollama сомелье не зовёт вовсе |
| `SVS_SOMM_INPUT` | `1` | `0` — поля вопроса нет, вопрос текстом — `422 {"detail": "вопрос текстом выключен"}`, чипы работают |
| `SVS_SOMM_DIR` | `$SVS_DATA_DIR/somm` | данные сомелье — и для чипа «К чему?» у полки |
| `SVS_SOMM_TIMEOUT_MS` | `4000` | предел живого голоса |
| `SVS_SOMM_QUIET_S` | `15` | тихое окно после каждого `/v1/eval/predict` |
| `SVS_SOMM_SAFETY` | `0` | `1` — смысловой слой барьера (rubert-tiny2 из локального кэша, CPU) |

`/v1/health` получает блок `somm` (`SommRuntime.stats`, `app/api/somm.py:220-244`): выключатели,
источник и счёт каждого файла данных, счётчики ворот (сканы, входы, отказы по причинам, обрывы,
время удержания и отдачи замка), счётчики голоса (вызовы, прошедшие, откаты по причинам и
проверкам), состояние смыслового слоя и число принятых вопросов. Данные не из `SVS_SOMM_DIR`
(заглушки договора или пустота) — `somm.status: "degraded"` с причиной по файлу и предупреждение в
общем `warnings`, которое читает `scripts/run_eval.sh`: сервис на семи винах заглушек больше не
выглядит готовым. Тело predict это не трогает.

- **На фейках** (без видеокарты и без Ollama): ворота, голос с поддельной Ollama, обрыв сканом,

- **На видеокарте — слитый код до ворот «только да».** Повторное окно 25.09 шло на `c0c4324`:
  зонд `scripts/somm_probe.py` на той же Ollama и модели, что у сервиса, — опции без перезагрузки
  (`reloads == 0`, `expires_at` не укорочен), доля прошедших проверки 0,949 на настоящих пакетах
  (порог плана — 0,7), `prompt_eval_count` против потолка 2 100 символов, `--service` насквозь
  через маршруты. Ворота «только да» (выше) и правки правил в данных после него на видеокарте не
  мерились: голос у «да» и «К чему подать» не менялся, а пакетов, которые он больше не видит,
  зонд не шлёт.
- **Полевая очередь мимо ворот.** Кадры `/v1/field/submit` разбирает фоновый поток
  (`app/api/field.py:343`) уже после ответа, мимо `FieldScanGate`: такой скан может подождать

## 12. Известные ограничения

- **Путь по умолчанию привязан к индексу.** Карта адаптера собрана под индекс `ccd3a01f…`.
  Пересборка индекса (новые эталоны, как в Э8) требует новой карты. Новая карта — новый артефакт:
  kr-test для неё уже потрачен, и проверять её можно только на новых отложенных данных. До тех
  пор с новым индексом — только `SVS_CANDIDATE=off`. С живыми карточками (`SVS_LIVE_CARDS=1`)
  то же самое.
- **На снимках, как у организатора, выигрыша нет.** R-оригиналы: 62 из 65 против 63 у прежнего
  пути с Э7 (§7). Замеренный прирост — на розничных снимках магазина (kr-test), и его уровень на ближнем
  домене оптимистичен.
- **Живой прогон публикуемой сборки — один.** 27.09, 100 «Реальных фото» и 3 публичных кадра
  (`research/2026-09-27_results/`). На kr-test она не прогонялась: тест израсходован, её ответы
  там выведены из равенства с `fund` бит в бит, кроме полей чтения R014 (§7).

- **Пороги.** Граница `ambiguous` 0,5 и `confidence.top5` не калибровались. Порог правила отказа
  ставился на сырых косинусах, а не на шкале zmax (`configs/resolve/README.md`, раздел про
  `visual_floor`).
- **Один воркер и один замок видеокарты.** Второй одновременный скан ждёт первого за счёт
  своего бюджета. Голос сомелье скан не задерживает дольше обрыва (§10), но пока идут сканы, живого
  текста нет — только шаблон.
- **Процессор вместо видеокарты.** Цепочка та же, но в 10 с скрипта организатора она не
  укладывается. На 4 ядрах один поиск по картинке идёт 13,5–14,0 с
  (`research/2026-09-23_docker-smoke/smoke.out`), ответ помечается `over_budget`. С бюджетами
  полевого стенда (600 000 / 540 000 мс, `deploy/svs-field.env.example:9-10`) цепочка полная,
  с чтением, но ответ идёт минуты.
- **Полевой контур.** По умолчанию выключен (`app/api/main.py:307-311`). С `SVS_FIELD=1`, но
  без `SVS_FIELD_TOKEN` страница стенда `/field` и `/v1/field/*` открыты всем.
- **Фото карточки — только выгрузки.** В публичный репозиторий `photos_small` не входит (§6, §8):
  без него на месте фото — силуэт бутылки. `photos_small` пересобран 24.09 из фото выгрузки
  организатора: замены правки эталонов 23.09 (живой портал, Роскачество) не показываются, 23 фото
  с чужим вином заменены силуэтом (§6). Файл карты фото `photo_file` берёт, только если лёгкой
  копии нет, и никогда — из `packshots_fixed` (`app/api/after_layer.py:586-589`). Если карту
  фото править снова, `photos_small` надо пересобрать с нуля: `deploy/pack_data.sh` о старых
  фото предупреждает, а о чужих — останавливается.
- **Сахар только из названия и slug.** У 376 из 2 103 позиций сахар неизвестен: у них нет оси
  сладости, похожие и «Сомелье у полки» подбирают без ступени сахара, «послаще» — честная нота
  `not_evaluable` (§9). Другого источника сахара у организатора нет.
- **Ссылка на портал — по карте сайта 04.09.** Страницы, опубликованные или снятые позже, не
  учтены: такая ссылка может вести в 404. Новый дамп — `scripts/build_portal_links.py`.
- **Описания организатора — как есть.** Оценочные слова и `%` внутри «Описания» выгрузки
  `content_filter` не режет: показывать как есть, обрезать или фильтровать — решение команды.
- **Сомелье: живой замер — одно окно.** На видеокарте 25.09 прошли проверки 166 из 175 настоящих
  пакетов (0,949, §10); на других вопросах проверки могут оказаться строгими.
- **Смысловой слой выключен.** Окольные фразы о зависимости, трезвости и здоровье без слова темы
  правила ловят плохо — 3 из 18, 4 из 10 и 3 из 14 (`research/2026-09-24_somm/safety_eval.json`).
  Для показа без риска — `SVS_SOMM_INPUT=0` (только чипы). Весов rubert-tiny2 в образе Docker
  нет: с `SVS_SOMM_SAFETY=1` в контейнере слой скажет `missing`. Подложить их можно в кэш тома
  `/hf/hub` только при `SVS_SIGLIP_AT_BUILD=0`: при `1` сервис читает кэш образа.

## 13. Стек ТЗ и встраивание в портал

### Без облачных API и больших языковых моделей

Сервис — код на Python и две открытые модели на одной машине с одной видеокартой. Ни одна модель
не вызывается через внешний API:

| Модель | Зачем | Размер | Где работает |
|---|---|---|---|
| SigLIP 2 so400m, `google/siglip2-so400m-patch14-384` | поиск по картинке | сервис грузит только зрительную башню: 1,71 ГБ весов float32 — около 0,4 млрд параметров (`scripts/trim_vision_weights.py:1-5`) | в процессе сервиса, на видеокарте |
| `qwen3.5:4b` | чтение этикетки; голос сомелье — только в тишину между сканами | 4 млрд параметров (`4b` в имени модели), 3,4 ГБ (§6) | Ollama на той же машине |

- **Одна видеокарта потребительского класса.** Обе модели вместе занимают 7 229 МиБ видеопамяти
  RTX 3080 10 ГБ (`research/2026-09-23_audit/clean_latency/summary_4b_8b.out:10`). Ответ на
  100 «Реальных фото» — p95 1,5 с (§4). Видеокарты меньше 10 ГБ не проверялись.
- **Остальное — процессор и миллисекунды.** Слой выбора — логистическая модель на 34 признаках
  (resolve — 1,3 мс, §4); рекомендации, правила сомелье и барьер — чистый Python.
- **Данные не уходят наружу.** Единственный сетевой вызов сервиса — к Ollama на той же машине
  (`app/reading/readers/ollama_vlm.py:76-82`, `app/sommelier/ollama_text.py`). Веса SigLIP —
  только из локального кэша (`app/features/embedder.py:138`; `HF_HUB_OFFLINE=1` —
  `Dockerfile:46`). Кадр и вопрос гостя не покидают машину и на диск не пишутся (§8). Интернет
  нужен один раз — скачать образ и веса.
- **Платы за запрос нет:** ни ключей API, ни тарифов, ни квот внешнего сервиса.
- **Поднимается одной командой** на обычном ПК с видеокартой NVIDIA:
  `docker compose --profile gpu up -d --build` (README, «Шаги на чистой машине»). Прогон 27.09
  снят именно так, из чистого клона. Без видеокарты работает профиль `cpu`, но в 10 с скрипта
  организатора он не укладывается (§12).

### Рекомендованный стек ТЗ и наш

| Рекомендовано в ТЗ | У нас | Почему |
|---|---|---|
| SigLIP 2 | SigLIP 2 so400m, float32, и адаптер LW поверх | so400m на dev по одной картинке: top-1 82,6 % студия и 73,8 % «телефон» против 73,2 % и 65,8 % у SigLIP 2 base (`bench/README.md:295-310`, §5). Адаптер — «Нормализация фото» (§2) |
| PostgreSQL + pgvector | индекс в памяти процесса: `data/index/visual-s2so400m.npz`, 18 МБ, 6 312 векторов × 1152 во float16 | 2 103 карточки × 3 вида перебираются целиком на CPU за 6,8 мс p50 (§2, слой 2): базе и приближённому поиску (ANN) здесь нечего ускорять. zmax стандартизует косинусы по всем векторам вида, а ANN отдаёт только ближайшие. Индекс — один файл в `data/`, сервис при старте сверяет его с картой адаптера (§2, слой 2) |
| Strapi CMS | ключ ответа — slug карточки Strapi; факты карточки — из выгрузки Strapi организатора `strapi_output0709.csv`; ссылка — на страницу портала `https://vino-svoe.ru/wines/<slug>` | живого подключения к Strapi нет: данных портала в продукте нет (решение 24.09, §6). Карточку по slug портал может брать из своей Strapi |
| Nuxt | страница продукта — один файл HTML и лист сомелье без сборки (`app/api/static/index.html`, `somm.js`, §9); сервис — JSON-API на FastAPI | наша страница — показ и образец вызовов API. На портале ту же роль играет страница Nuxt, которая зовёт те же маршруты (ниже) |
| Docker | `Dockerfile` строго по `uv.lock`, `compose.yml` с профилями `gpu` и `cpu` (§11) | как в ТЗ; прогон 27.09 — Docker из чистого клона |
| — | Ollama и `qwen3.5:4b` читают этикетку | текст этикетки добавляет к картинке: обученный выбор с чтением на dev — 85,2 % студия и 78,5 % «телефон», без текста — 81,2 % и 73,2 % (`bench/README.md:295-310`). С RapidOCR вместо VLM — 83,2 / 75,2 (§5) |

**Путь к pgvector** (не сделан и не мерился). Векторы эталонов лежат в таблице
`slug, view, vector` с индексом ANN. Сервис берёт по каждому окну запроса top-N из базы и уже на
них считает zmax и ранкер. Среднее и σ косинусов запроса по всему виду zmax нужны целиком, а не
по top-N; для единичных векторов они точно считаются из среднего и ковариации векторов вида,
которые сервис держит у себя и пересчитывает при смене каталога. Смысл появится, когда каталог
вырастет на порядки или векторы нужно будет хранить рядом с карточками портала.

### Встраивание в портал

```
страница Nuxt или маршрут каталога
   │  фото с камеры или из галереи
   ▼
POST /v1/scan  (multipart `image`, ≤ 25 МБ; JPEG, PNG, WebP, HEIC, AVIF)
   │  slug, confidence, margin, top5 + card, candidates, after
   ▼
карточка Strapi по slug (/wines/<slug>) · «Не то вино?» · похожие · сомелье
```

1. Страница портала шлёт кадр в `POST /v1/scan`. CORS сервис не включает, поэтому вызов идёт с
   сервера Nuxt (серверный маршрут) или через общий обратный прокси с адресом портала.
2. Ответ — `slug`, `confidence.top1` и `top5`, `margin`, `top5`, а для экрана — `card`,
   `candidates` и `after` (§3).
3. `after.state = found` — портал открывает свою карточку Strapi по slug. `check` — показывает
   варианты из `candidates` («Не то вино?») и вопрос `after.question`. Флаг `suggest_not_found` —
   кнопка «Моего вина здесь нет» → `POST /v1/similar/by-label`. Похожие и сомелье —
   `/v1/wines/{slug}/similar`, `/v1/wines/{slug}/sommelier`, `/v1/sommelier/ask` (§3).
4. **Сервис без состояния.** Кадр живёт в памяти запроса и на диск не пишется, учётных записей
   нет, разговор с сомелье хранит вкладка браузера (§8). Ставится одним контейнером рядом с
   порталом. Один экземпляр — одна видеокарта и один воркер (§12); несколько экземпляров за
   балансировщиком не проверялись.

### Пополнение каталога

ТЗ ждёт около 50 новых вин в день. Автоматического конвейера из Strapi нет: новые карточки
попадают в поиск пересборкой данных скриптами репозитория и перезапуском сервиса — данные
читаются при старте.
1. Признаки карточек — `scripts/build_gt_tokens.py --csv <новая выгрузка>`. Кроме CSV ему нужны
   рабочие таблицы двойников и алиасов виноделен (`--clusters`, `--winery-map`, `--live`); в
   публичный репозиторий они не входят.
2. Словарь — `scripts/build_lexicon.py`.
3. Векторы — `scripts/build_index.py --photo-map <slug,path> --model
   google/siglip2-so400m-patch14-384 --device cuda --out data/index/visual-s2so400m.npz`. Модель
   и выход нужно указать явно: по умолчанию скрипт берёт SigLIP base (`DEFAULT_MODEL`,
   `app/features/embedder.py:29`) и пишет `data/index/visual.npz`, а сервис читает
   `visual-s2so400m.npz`. Индекс пересчитывается целиком. Порядок всех шагов с обучением —
   README, «Подготовка данных и обучение».
4. Фото, данные сомелье и ссылки — `scripts/make_photo_pack.py`, `scripts/build_somm.py`,
   `scripts/build_portal_links.py`; архив для сервера — `deploy/pack_data.sh`.

Ограничения (§12):
- **Карта адаптера привязана к индексу `ccd3a01f…`.** С новым индексом путь по умолчанию не
  стартует. Остаётся прежний путь `SVS_CANDIDATE=off` (kr-test 89,6 % против 94,5 %) или новая
  карта (`research/2026-09-26_fund/final/build_final.py`) с проверкой на новых отложенных данных:
  kr-test уже израсходован.
- **Сверка сборки.** Новые признаки и словарь дают `provenance.consistent=false`, пока новый
  эталон не объявлен производной в `configs/resolve/gt_lineage.json` (как `live71`) или ранкер
  не переобучен (§11). Отчётный прогон `scripts/run_eval.sh` с такой сборкой не идёт.
- **Дописывание без пересчёта старых карточек** есть как механика: строки новых карточек идут за
  строками базы, маска `base_rows` держит нормировку zmax по базе, и счёт старых карточек не
  меняется (`app/features/index.py:71-132`, `scripts/build_live_set.py`). Проверена на 71
  карточке живого портала (Э3, §7). Работает только на прежнем пути, а скрипт пока пишет лишь
  комплект `*-live71`.
- **Время пересборки** на 50 новых карточек не мерилось.
