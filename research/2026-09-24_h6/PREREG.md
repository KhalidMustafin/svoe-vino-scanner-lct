# H6: прочитанное решает выбор внутри винодельни — условия проверки (заданы до замера)

Записано 24.09 до того, как правило посчитано на полном наборе. Коммит этого файла — отметка
времени: код замера и отчёт появляются только после него.

## Откуда правило

Разбор 48 ошибок контрольного прогона `pfix_final` (сервис после правки эталонов, qwen3.5:4b + H5)
на `sets/catalog_v2` (353 кадра, 226 вин): 39 ошибок — верная винодельня, соседнее вино. Примерно
в 13 из них читатель прочитал отличающее слово («БРЮТ», «СЛАДКОЕ», «ПОЛУСУХОЕ», пару сортов), а
слой выбора взял соседа. Отсев H5 по сахару и цвету работает только при p_top1 < 0,5; поднять
порог нельзя: при пороге 0,6–1,0 починок 7–12, поломок 3–13 — отсев уводит к другим винодельням и
спотыкается об ошибки атрибутов карточек.

**Честно:** правило придумано после просмотра ошибок на тех же 353 кадрах, отложенного набора нет.
Поэтому вариант один, без параметров и без подбора; источники атрибутов — два, оба названы здесь.

## Правило H6

Применяется после H5 к итоговому ответу `A` любого кадра (при любом p_top1).

Прочитанное (`LabelFields` кадра, как его строит сервис):
- `S` — классы сахара из `fields.sugar`;
- `c` — цвет из `fields.color`;
- `G` — коды сортов из `fields.grapes`, приведённые `grape_key`, и только те, что встречаются как
  код сорта хотя бы у одной карточки каталога (сырые слова вроде «каберне» отбрасываются).

Для карточки `x` с атрибутами `sugar(x)`, `color(x)`, `grapes(x)` (пусто = неизвестно):
- `conflict(x)` = `contradicts(x, fields, attrs)` из `app/resolve/ambiguous.py` (сахар или цвет
  спорят, обе стороны известны) **или** (`G` не пусто, `grapes(x)` не пусто и `G ∩ grapes(x) = ∅`);
- `support(x)` = (`S` не пусто и `sugar(x) ∈ S`) или (`c` известен и `color(x) = c`) или
  (`G ∩ grapes(x) ≠ ∅`).

Если `conflict(A)`: идём по порядку обученного слоя (`ranking.slugs`, 20 кандидатов, `A`
пропускаем) и берём первого `y`, у которого винодельня та же, что у `A` (`norm_key(winery)` равны и
не пусты), `conflict(y)` ложно и `support(y)` истинно. Нашёлся — ответ `y`. Нет — ответ `A`.

## Два источника атрибутов (оба заявлены заранее)

- **H6-svc** — `CatalogAttrs` сервиса (`data/gt/gt_tokens.jsonl`), тот же, что у H5.
- **H6-dict** — справочник вин `field_dataset/catalog/wines_final.jsonl` (сахар из живой категории
  и slug, правки перепроверки 23.09) через `sugar_key` / `color_key` / `grape_key` / `norm_key`;
  slug вне справочника — атрибуты сервиса.

## Замер

- Входы — только дампы, видеокарта не нужна: `runs/field25/iters/runs/pfix_final/iter20`
  (`predictions.jsonl`: `resolve` — порядок слоя, 20 кандидатов; `vlm`/`text_read` — чтение).
- **Ворота исправности:** пересчёт H5 из дампа совпадает с ответами `pfix_final` на 353 из 353.
  Не совпало — замер не идёт, сначала разбор.
- База — H5 `pfix_final`: «то же вино» 86,0 макро / 86,4 микро, строго микро 84,1.

## Решение (для каждого источника)

Вариант принят, только если выполнено всё:
1. починок ≥ 4 × поломок и починок ≥ 3;
2. строгий микро не ниже базы;
3. ни на одном срезе (R, M, L) чистое изменение «то же вино» не отрицательное.

Прошли оба — берём с большим строгим микро; поровну — H6-svc (без новой зависимости данных).
Не прошёл ни один — сервис не меняется, в отчёт идёт разбор поломок.

## Только для сведения (на решение не влияет)

- Разложение: только сахар и цвет; только сорта.

  «нет в каталоге».
