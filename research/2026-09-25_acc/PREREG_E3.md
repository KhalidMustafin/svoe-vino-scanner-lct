## Уточнения до замера

1. **База и правила Э1.** База — сервис `after-search` @7b76247 (H5 в `service._resolve`). Принятых
   правил Э1 на момент записи нет: Э1 идёт параллельно и ещё не решён. Поэтому замер идёт без
   правил Э1: «замороженный ранкер → H5». Повторного просмотра kr после решения по Э1 не будет;
   совместимость со сборкой проверяет тест равенства при слиянии в `acc-freeze`.

2. **Комплект «живой» (флаг включён) — ровно 71 карточка.**
   - Индекс: 6 312 строк `data/index/visual-s2so400m.npz` без изменений (те же float16, тот же
     порядок) + строки `07b02d3881dc2055.npz`, чьих slug нет в базе (ожидается 213 = 71 × 3), в
     порядке файла. Маска `base_rows`: первые 6 312 — `true`, добавленные — `false`.
   - gt: 2 103 строки `data/gt/gt_tokens.jsonl` байт в байт + 71 запись из
     `new_cards_gt_tokens.jsonl`. В файле 73 записи. Две записи — дубли вин CSV (`chardonnay-2024`,
     `merlo-2`). Они не входят ни в индекс, ни в gt, ни в словарь: иначе словарь знал бы слова карточек,
     которых нет в выдаче. Это расхождение с формулировкой пункта (3) плана.
   - Словарь: `scripts/build_lexicon.py` этой же ветки по живому gt. Проверка сборщика: он же по
     базовому gt воспроизводит `data/index/lexicon.json` байт в байт.
   - Флаг — переменная `SVS_LIVE_CARDS`. Она переключает умолчания трёх путей вместе: индекс, gt,
     словарь. Явные `SVS_INDEX_PATH` / `SVS_ATTRS_PATH` / `SVS_LEXICON_PATH` по-прежнему главнее.
     Умолчание флага ставится по воротам kr (ниже), а не по v2.

3. **Форма замера (одна для v2, kr и ooc_v2).** План говорит «replay.py по векторам запросов». Но
   `replay.py` берёт поля чтения из дампа, а дампа kr с живым словарём нет. Поэтому замер идёт
   так:
   - Сам сервис ветки (`ScannerService.load`) грузит оба комплекта флагом.
   - Поиск по картинке — `index._rank` загруженного индекса по CPU-векторам запросов. Это и есть
     проверяемый код.
   - Векторы запросов: v2 — `qemb_catalog_v2.npz`. kr и ooc_v2 — `qemb_kr.py` и его копия для
     ooc_v2: тот же путь, что `qemb.py` (CPU, `decode_on_backgrounds` → `from_query` → SigLIP2
     so400m float32, хранение float16). Меняются только порядок (сначала 617 основных) и
     контрольные точки.
   - Чтение — из кэша чтений стенда (`runs/field25/iters/cache/reads`, читатель
     `vlm|qwen3.5:4b|f3a017317f04`). Разбор — `read_label` сервиса со словарём своего комплекта.
     Промах кэша — ошибка кадра, а не вызов Ollama. Видеокарта и Ollama не используются.
   - Код разбора чтения в ветке совпадает со снимком `snap/iter20`, на котором сняты дампы (сверено
     без учёта CRLF). Справочно показываются: (а) совпадение полей, разобранных базовым словарём,
     с полями дампа; (б) совпадение ответа H5 базового комплекта с ответом дампа (CPU-векторы
     против GPU-векторов). Воротами эти две сверки не являются.
   - Сравнение «флаг выкл. против флаг вкл.» идёт на одних и тех же векторах запросов и одних и
     тех же чтениях. Разница — только комплект.

4. **Ворота кода, точная форма.** На векторах запросов всех кадров v2 (353) и kr (903) должны
   совпасть бит в бит top-20 (slug, score, view, rank), отрыв (margin) и ответ H5:
   - (а) код @7b76247 (старые `align_pairs` / `VisualIndex`) против кода ветки с базовым индексом
     без маски (флаг выключен);
   - (б) код @7b76247 против кода ветки на базовом индексе с маской «все строки базовые»
     (добавлений нет).

   Справочно, не ворота: в живом индексе счёт каждого slug CSV при заморозке равен его счёту в
   базовом индексе (max |Δ| по top-20 базы).

5. **Счёт смен на kr.** Кадр засчитывается как «смена ответа на другое вино», если ответ H5 при
   включённом флаге не равен ответу при выключенном и не входит в ту же группу вина по
   `field_dataset/catalog/wine_groups_final.json`. Истина кадра для этого счёта не нужна; сколько
   из смен — поломки или починки, показывается отдельно.
   - По §5 плана решение по kr принимается по двум счётам: чтения как есть и без водяного знака.
     Второй счёт — правило `strip_wm` из `acc_plan/errors_holdout/wm_whatif.py`, применённое к
     разобранным полям обоих комплектов. Для решения берётся **больший** из двух счётов смен.
   - Набор решения — 617 основных кадров (`same_packshot=false`). 286 почти копий — только в
     воротах кода и справочно.
   - Кадры Э4(S1) не исключаются: Э4 не принят, атрибуты карточек CSV в живом комплекте байт в
     байт базовые.

6. **v2, точная форма приёмки.**
   - «Кадры с эталоном в CSV»: эталон `slug` или любой из `acceptable` есть в базовом gt.
   - Поломка / починка — «то же вино» (`slug ∪ acceptable`) против ответа при выключенном флаге.
   - «Поломок на R» — по всем кадрам среза R.
   - Числа микро, макро, строго и по срезам — как в `replay.score`.

7. **ooc_v2 (справочно).** Векторы снимаются на CPU после kr, если хватит времени до 18:00 МСК.
   Показывается доля кадров, чей ответ при включённом флаге — одна из 71 карточки. На решение не
   влияет.
