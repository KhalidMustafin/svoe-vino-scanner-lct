### 3. Шесть признаков (`resolve-features/4`)

Для читателя `r` (у A3 — `vlm35`), по кандидатам top-20 одного запроса:

- `r.{f}_match_unique` для f ∈ {grape, sugar, color, winery, cuvee} = `r.{f}_match / n_f`, где
  `n_f` — число кандидатов запроса с `r.{f}_match = 1`; при `r.{f}_match = 0` — 0;
- `r.grape_jaccard` = |сорта прочитанные ∩ сорта кандидата| / |∪|; сорта прочитанные —
  `read_fields(fields, attrs).grapes`, сорта кандидата — `WineAttrs.grapes`; сорт не прочитан или
  кандидата нет в каталоге — 0.

Это ровно `augment()` из `acc_plan/selection/common.py`. В коде — новая текстовая группа
`unique` в `app/resolve/features.py`, считается всегда, как прочие группы.

- **`FEATURE_VERSION` → `resolve-features/4`.** Смысл 34 прежних признаков не меняется, поэтому
  модель версии `/3` загружается, если все её признаки — признаки версии `/3`. Так замороженная
  `-goal` (`configs/resolve/s2so400m-vlm35-goal.json`, sha1 `be51adb7`) остаётся файлом без правок.
  Модель `/3` с чужим признаком и любая другая версия по-прежнему не загружаются.
- **Сверка кода с 25.09:** на всех кадрах v2, kr и студии значения шести признаков из
  `features.py` = копии `augment()` из `common.py` (бит в бит). Не сошлось — ищу ошибку в коде.

### 4. Обучение A3 (`bench/train_hybrid.py`)

- **Признаки:** 34 признака `-goal` в её порядке + 6 новых в порядке `common.py`
  (grape, sugar, color, winery, cuvee `_match_unique`, затем `grape_jaccard`).
- **Модель:** `LogisticRanker(listwise, l2=0,01)`; знаки 34 — `feature_signs` кода, 6 новых — +1.
- **Студия — 298 запросов:** прогоны CV и OCR из `meta` модели `-goal` (`cv_files`,
  `ocr_files`), функция `bench.train_resolve.load_split`, половина `dev`, top-20. Чтения — как
  записаны в прогонах OCR (их видела `-goal`), признаки — с атрибутами `899d5db3`. Позитив —
  эталонный slug; запрос без него в top-20 выпадает сам (`LogisticRanker.fit`).
- **v2 — 353 кадра:** входы стенда `acc-freeze`, метки `catalog_v2/meta.jsonl` (slug ∪
  acceptable). Правило R1 из `common.py`: позитив — строка эталонного slug, а если её нет в
  top-20 — верный кандидат с лучшим рангом CV; прочие верные строки этого кадра из обучения
  удаляются. Кадр без верного в top-20 выпадает.
- **krasnostop в обучение не входит.**
- **Температура A3 не калибруется** (T = 1) и нигде не используется: калитка берёт p у `-goal`,
  а числа `confidence` и `top5[].score` сервис по-прежнему показывает по вероятностям `-goal`
  (как у H5 и P1 сейчас).
- Обучение детерминировано (Ньютон без случайности); `seed` задаёт только разбиение OOF.

### 5. Калитка в `service._resolve`

- p — вероятность лидера `-goal` до любых перестановок: та же, по которой H5 решает «спорный
  кадр».
- **p < 0,5** — путь прежний: H5 (`rerank_ambiguous`).
- **p ≥ 0,5** — ответ — argmax счёта A3 по тем же 20 кандидатам, top-5 — первые пять по счёту
  A3; при равенстве счётов выше тот, у кого лучше ранг CV. **P1 здесь не применяется**: его
  место занимает A3 (так считался и прирост «поверх P1» 25.09).
- `outcome` по-прежнему от p: `matched`. В `evidence.resolve` — `hybrid` (калитка открыта) и
  `hybrid_changed` (ответ A3 ≠ лидеру `-goal`). Ключи тела `/v1/eval/predict` не меняются.
- **Выключатель:** `SVS_HYBRID_MODEL` — путь к модели A3, по умолчанию файл сборки;
  `off` / `0` / `none` — без A3, то есть ровно поведение `acc-freeze` (P1 при p ≥ 0,5). Правка
  кода для отката не нужна.

### 6. Замер (1): OOF на v2

- **Группы** — связные компоненты «вино» по `catalog_v2/meta.jsonl`: union-find по slug ∪
  acceptable ∪ `source` кадра (`components()` из `common.py`).
- **Фолды** — `group_folds()` из `common.py`: группы в перестановке `default_rng(seed)`, каждая —
  в самый лёгкий по числу кадров фолд, при равенстве — в меньший номер. 5 фолдов, seeds 0–4.
- На фолде k: A3 учится на студии (298) + кадрах v2 вне фолда k и отвечает на кадрах фолда k.
- Ответ гибрида на кадре — ответ базы при p < 0,5, иначе argmax A3 этого фолда.
- **Счёт против базы** (`acc-freeze`, ответы стенда) на всех 353 кадрах: мягко — slug ∪
  acceptable, строго — slug; срезы R / M / L по первой букве `photo`.
- **Приёмка на КАЖДОМ из 5 разбиений** (механически):
  - мягко починок ≥ 4 × поломок;
  - поломок на R = 0;
  - верных в R, M и L — не меньше, чем у базы (63, 233, 19);
  - строго микро не ниже (≥ 307 из 353).
- **Порядок:** если хоть одно разбиение не прошло — Э5 отклонён, kr **не открывается** (просмотр
  не нужен для решения и не тратится), из Э5 ничего не сливается.

### 8. Замер (3): тест равенства

- `bench/resolve_equality.py` получает офлайн-сторону гибрида: счёт A3 — numpy по весам файла
  (`z = (x − mean) / scale`, `s = z·w + b`), порядок по убыванию, при равенстве — лучший ранг CV;
  при p ≥ 0,5 ответ — первый по A3, иначе H5.
- Требование: `service._resolve` = офлайн на 353/353 (`pfix_final`) и 617/617 (`kr_holdout`) с
  A3; и с выключенным A3 — прежние ответы `acc-freeze` (P1).
- Дополнительно: `service._resolve` ветки на входах стенда `acc-freeze` = ответы замера на
  353/353 v2 и 903/903 kr.
